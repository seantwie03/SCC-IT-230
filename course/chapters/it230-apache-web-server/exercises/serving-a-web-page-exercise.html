Serving a Web Page Exercise

Task

Stand up a web server on servera, publish two pages, and reach them from workstation. Getting the second part to work is most of the lesson.

Hosts
servera and workstation
Home page
http://servera/
Second page
http://servera/about/contact-us.html

  1. Install httpd

    sudo -i
dnf install -y httpd
systemctl is-enabled httpd
systemctl is-active httpd
    Installed is not running httpd ships disabled and stopped. Installing a service on RHEL never starts it for you.

  2. Write a home page

    Check where Apache serves from, then write a file there. 

    grep DocumentRoot /etc/httpd/conf/httpd.conf
vim /var/www/html/index.html
    Welcome to servera

  3. Enable and start the service

    systemctl enable --now httpd
systemctl is-active httpd
curl http://localhost/

  4. Add a page in a subdirectory

    mkdir /var/www/html/about
vim /var/www/html/about/contact-us.html
    Contact Us
    curl http://localhost/about/contact-us.html
    The URL is the path /var/www/html/about/contact-us.html is served at /about/contact-us.html. Apache maps URL paths straight onto the filesystem under DocumentRoot.

  5. Reach both pages from workstation

    Leave servera and try from the other machine. 

    exit
ssh workstation
curl --max-time 5 http://servera/

    It times out. The pages work locally and not remotely, which is the classic symptom. 

    exit
sudo firewall-cmd --add-service=http --permanent
sudo firewall-cmd --reload
sudo firewall-cmd --list-services

    Now try again from workstation.

    ssh workstation
curl http://servera/
curl http://servera/about/contact-us.html
exit
    Two gatekeepers, not one firewalld was the first. SELinux is the second, and it is next week's subject. A web server that works locally but not remotely is nearly always one of these two.

  6. Clean up

    sudo firewall-cmd --remove-service=http --permanent
sudo firewall-cmd --reload
sudo systemctl disable --now httpd
sudo rm -rf /var/www/html/index.html /var/www/html/about
sudo dnf remove -y httpd
