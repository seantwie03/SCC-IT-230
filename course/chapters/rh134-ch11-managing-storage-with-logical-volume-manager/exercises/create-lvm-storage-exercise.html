Exercise

Create LVM Storage Exercise

Task

Build a complete LVM stack on servera in one pass: pool the blank disks /dev/sdb and /dev/sdc into one volume group, carve a swap logical volume and a larger one for an XFS file system on /records, and make both persistent. Use the Procedure: Create a Logical Volume slides as your reference. The next exercise grows both volumes, so leave them in place when you finish.

Host
servera
Prerequisite
Remove the LVM Setup Exercise

  1. Create an lvm partition using all of /dev/sdb, and another using all of /dev/sdc 

    sudo -i
lsblk
parted /dev/sdb mklabel gpt
parted /dev/sdb mkpart primary 1MiB 100%
parted /dev/sdb set 1 lvm on
parted /dev/sdc mklabel gpt
parted /dev/sdc mkpart primary 1MiB 100%
parted /dev/sdc set 1 lvm on
udevadm settle
lsblk /dev/sdb /dev/sdc

    Check with the first lsblk that sdb and sdc are blank, and use the names it shows if yours differ. An end of 100% runs each partition to the end of its disk, so the last lsblk shows sdb1 and sdc1 at 5G each.

  2. Initialize both as physical volumes and create a volume group named vg_storage from them 

    pvcreate /dev/sdb1 /dev/sdc1
vgcreate vg_storage /dev/sdb1 /dev/sdc1
vgs vg_storage

    vgs shows two physical volumes and about 9.99g, all of it free.

  3. Create a 1 GiB logical volume named lv_swap, and one named lv_records from the rest of the space 

    lvcreate --name lv_swap --size 1G vg_storage
lvcreate --name lv_records --extents 100%FREE vg_storage
lvs vg_storage

    Both lvcreate commands may ask WARNING: xfs signature detected on /dev/vg_storage/lv_swap at offset 0. Wipe it? [y/n]:, the second about lv_records. lv_swap starts where lv_data began in the earlier exercises, and lv_records starts at the beginning of /dev/sdc1, where lv_data's XFS kept a copy of its superblock after growing onto that disk. The removal steps left both behind. Type y and press Enter each time to wipe them. lvs then lists lv_swap at 1.00g and lv_records at about 8.99g.

    One volume, two disks lv_records is larger than either disk, so its extents span both. That is LVM's strength, and its risk: if either disk fails, the whole logical volume is lost, unless the disks beneath it are themselves redundant.

  4. Format lv_records with XFS and persistently mount it on /records 

    mkfs.xfs /dev/vg_storage/lv_records
mkdir /records
vim /etc/fstab

    In vim, press G and then o to open a new last line, type this line, press Esc, and save with :wq: 

    /dev/vg_storage/lv_records /records xfs defaults 0 0
    systemctl daemon-reload
mount /records

  5. Format lv_swap as swap space and persistently activate it 

    mkswap /dev/vg_storage/lv_swap
vim /etc/fstab

    Add another last line the same way. A swap line uses swap as its mount point: 

    /dev/vg_storage/lv_swap swap swap defaults 0 0
    tail -3 /etc/fstab
systemctl daemon-reload
swapon -a

    tail shows your two lines last. swapon -a activates every swap line in /etc/fstab that is not already active.

  6. Verify with lsblk, df, and swapon --show

    lsblk
df -h /records
swapon --show

    lsblk shows vg_storage-lv_swap as [SWAP] under sdb1, and vg_storage-lv_records on /records under both sdb1 and sdc1. df reports about 9.0G. swapon --show lists the new swap space as /dev/dm-2, its kernel device name, beside the system's own /dev/dm-1.
