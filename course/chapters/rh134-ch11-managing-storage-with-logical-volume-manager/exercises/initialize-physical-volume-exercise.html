Exercise

Initialize a Physical Volume Exercise

Task

Create a 512 MiB partition on the blank disk /dev/sdb on servera, flag it for LVM, and initialize it as a physical volume. The next exercise builds a volume group on it, so leave it in place when you finish.

Host
servera
Prerequisite
None

  1. Create a 512 MiB GPT partition with the lvm flag on /dev/sdb 

    sudo -i
lsblk

    sdb, sdc, and sdd are blank 5 GiB disks with nothing beneath them. Use the name lsblk reports if yours differs from sdb, and never partition the disk that holds / and /boot.

    Open the disk in parted's interactive mode. Write a GPT label, create the partition, and set its lvm flag. Type each answer after its prompt, and press Enter alone at the file system type to accept the default. 

    parted /dev/sdb
(parted) mklabel
New disk label type? gpt
(parted) mkpart
Partition name?  []? pv1
File system type?  [ext2]?
Start? 1MiB
End? 513MiB
(parted) set
Partition number? 1
Flag to Invert? lvm
New state?  [on]/off? on
(parted) print
(parted) quit
udevadm settle

    The partition starts at 1 MiB, so ending it at 513 MiB makes it exactly 512 MiB, room enough for the XFS file system a later exercise puts on it, since XFS needs more than 300 MB. print lists partition 1 named pv1 with the lvm flag. It also shows ext2 in the File system column, but that is only the type hint you accepted: no file system exists, and the lvm flag is what marks the partition.

    Why a partition, not the whole disk pvcreate also accepts a whole disk such as /dev/sdb. A physical volume on a bare disk, though, looks empty to parted and to plain lsblk, and parted's mklabel overwrites it without asking. A partition flagged lvm shows people and tools what the disk holds, which is why partitions are the recommended practice.

  2. Initialize /dev/sdb1 as a physical volume

    pvcreate /dev/sdb1

    pvcreate answers Physical volume "/dev/sdb1" successfully created.

  3. Verify with pvs and pvdisplay

    pvs
pvdisplay /dev/sdb1

    pvs lists /dev/sdb1 at 512.00m with an empty VG column, beside the system's own /dev/sda3. pvdisplay calls it a new physical volume of 512.00 MiB, with no volume group, not yet allocatable, and no physical extents. It gets its extents when it joins a volume group in the next exercise.
