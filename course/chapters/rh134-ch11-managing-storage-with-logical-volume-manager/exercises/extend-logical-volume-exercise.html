Exercise

Extend a Logical Volume Exercise

Task

Fill the logical volume lv_data on servera until writes fail, then give it more room without unmounting /data: add a partition on a second disk to the volume group vg_data, extend lv_data by 200 MiB, and grow its XFS file system. The next exercise removes the whole LVM setup, so leave it as it is when you finish.

Host
servera
Prerequisite
Create a Logical Volume Exercise

  1. Fill lv_data completely

    sudo -i
df -h /data
dd if=/dev/zero of=/data/bigfile bs=4k

    df shows the file system on lv_data at 444M with 410M available. dd copies zeros from /dev/zero into /data/bigfile 4 KiB at a time, the size of an XFS block. With no count= to stop it, it keeps going until not even one block is left, then stops with dd: error writing '/data/bigfile': No space left on device after about 410 MiB. That error is the result you want here.

  2. Confirm that further writes fail with "No space left on device" 

    df -h /data
echo "test" > /data/testfile

    df reports the file system 100% used, with only about 28K available, which XFS keeps for itself. The echo fails with -bash: /data/testfile: No space left on device: there is no room even to create the file, so no testfile appears.

  3. Add a 512 MiB lvm partition on /dev/sdc to vg_data without unmounting /data

    /dev/sdc is the second blank disk; run lsblk first if your disk names differ. Partition it as you did /dev/sdb in the Initialize a Physical Volume Exercise, naming the partition pv2 and pressing Enter alone at the file system type. 

    parted /dev/sdc
(parted) mklabel
New disk label type? gpt
(parted) mkpart
Partition name?  []? pv2
File system type?  [ext2]?
Start? 1MiB
End? 513MiB
(parted) set
Partition number? 1
Flag to Invert? lvm
New state?  [on]/off? on
(parted) print
(parted) quit
udevadm settle

    Then initialize the partition as a physical volume and add it to vg_data: 

    pvcreate /dev/sdc1
vgextend vg_data /dev/sdc1
vgs vg_data

    vgextend answers Volume group "vg_data" successfully extended, and vgs shows two physical volumes, 1016.00m in all, and 508.00m free: the new partition's 127 extents. /data stayed mounted the whole time.

  4. Extend lv_data by 200 MiB

    lvextend --size +200M /dev/vg_data/lv_data
lvs vg_data

    The + adds to the current size. lvextend reports Size of logical volume vg_data/lv_data changed from 508.00 MiB (127 extents) to 708.00 MiB (177 extents)., and lvs lists lv_data at 708.00m.

  5. Grow the XFS file system

    xfs_growfs /data
df -h /data

    lvextend grew the logical volume, not the file system inside it, so /data is still full. xfs_growfs grows XFS to fill the volume. It takes the mount point, not the device, because XFS grows only while it is mounted. df then shows 644M with about 197M available.

    One command for both lvextend --resizefs --size +200M /dev/vg_data/lv_data would have extended the logical volume and grown its file system together. On ext4, the second step is resize2fs /dev/vg_data/lv_data, which takes the device instead of the mount point.

  6. Confirm that writes to /data succeed again

    echo "test" > /data/testfile
cat /data/testfile

    The echo that failed in the second step now succeeds without a message, and cat prints test.
