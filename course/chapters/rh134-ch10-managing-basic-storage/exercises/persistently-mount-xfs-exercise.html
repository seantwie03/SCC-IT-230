Persistently Mount an XFS File System Exercise

Task

Add an entry to /etc/fstab on servera so the XFS file system on /dev/sdb1 mounts on /records at every boot. Test the entry without rebooting, then reboot to confirm it.

Host
servera
Prerequisite
Create File Systems Exercise

  1. Inspect /dev/sdb

    sudo -i
lsblk -fp /dev/sdb

    /dev/sdb1 reports xfs and a UUID, and its MOUNTPOINTS column is empty. If it shows /mnt/records, the previous exercise left it mounted; run umount /mnt/records first.

  2. Create the mount point /records

    mkdir /records
ls /

    ls / now lists records among the top-level directories.

  3. Persistently mount /dev/sdb1 on /records

    Append the file system's UUID to /etc/fstab instead of typing all 36 characters, then check the new last line. 

    lsblk -no UUID /dev/sdb1 >> /etc/fstab
tail -1 /etc/fstab

    -n leaves out the header and -o UUID prints only the UUID column, so the command appends exactly one line: the bare UUID, without UUID= in front.

    Use >>, not > >> appends to the file. A single > replaces all of /etc/fstab with that one line, erasing the entries for /, /boot, and swap. If that happens, do not reboot; ask your instructor to help restore the file.

    Finish the line in vim.

    vim /etc/fstab

    Press G to go to the last line, then I to insert at its start, type UUID=, and press Esc. Press A to append to the end of the line, type /records xfs defaults 0 0 with a space in front, press Esc, and save with :wq. The finished line has six fields: 

    UUID=your-uuid /records xfs defaults 0 0

    Check the end of the file, then tell systemd, which builds its mount units from /etc/fstab, to read it again. 

    tail -5 /etc/fstab
systemctl daemon-reload

  4. Test with mount -av

    mount -av
restorecon -Rv /records
lsblk -fp /dev/sdb

    mount -av mounts every entry in /etc/fstab that is not mounted yet and reports each one; /records should end with successfully mounted. A mistake in the new line shows up here as an error, while it is still safe to fix. lsblk then shows /records in the MOUNTPOINTS column.

    The SELinux warning is expected The first mount of a new file system warns that /records does not contain SELinux labels, because nothing has labeled it yet. restorecon -Rv /records labels it, so the warning does not come back.

  5. Reboot and verify

    reboot

    The SSH session ends while servera restarts. Wait for it to finish booting, then connect again and check the mount without running mount yourself. 

    ssh servera
lsblk -fp /dev/sdb

    /dev/sdb1 shows /records in the MOUNTPOINTS column: the system mounted it at boot. Leave the entry and /records in place; a later exercise cleans them up.
