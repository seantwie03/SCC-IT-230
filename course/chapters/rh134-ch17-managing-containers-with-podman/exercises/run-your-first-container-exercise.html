Exercise

Run Your First Container Exercise

Task

A developer has an application built for a newer RHEL release than servera runs. Install Podman on servera, run a command in a Red Hat Universal Base Image (UBI) 10 container, and see which parts of the system the container brings with it and which it shares with its host.

Host
servera
Prerequisite
None

  1. Install Podman

    Connect to servera from your terminal and install the podman package. 

    ssh servera
sudo dnf install -y podman

    dnf installs podman and the packages it needs, about 17 in all, and ends with Complete!. If Podman is already installed, dnf says so and changes nothing. Remember the package name: an exam system may not have it.

    No container-tools in RHEL 10 Guides written for RHEL 9 install Podman with the container-tools package. RHEL 10 does not have it; install podman itself.

  2. Check the Podman version

    podman -v
    podman version 5.4.0

  3. Compare the RHEL release in a UBI 10 container and on servera

    Run cat /etc/redhat-release in a container from the UBI 10 image, then on servera itself. 

    podman run registry.access.redhat.com/ubi10/ubi cat /etc/redhat-release
cat /etc/redhat-release

    The first time, Podman downloads the image, about 80 MB, and prints its progress before the container's output: 

    Trying to pull registry.access.redhat.com/ubi10/ubi:latest...
Getting image source signatures
Checking if image destination supports signatures
Copying blob 6cbfcbeb6614 done   |
Copying config 7474288886 done   |
Writing manifest to image destination
Storing signatures
Red Hat Enterprise Linux release 10.3 (Coughlan)

    The container reports a newer release than servera, which reports Red Hat Enterprise Linux release 10.0 (Coughlan). Your numbers may differ: the image's latest tag moves to each new UBI release, and the blob and config IDs change with it. The files a program sees inside the container come from the image, not from the host.

  4. Compare the kernel in a UBI 10 container and on servera 

    podman run registry.access.redhat.com/ubi10/ubi uname -r
uname -r

    The image is already downloaded, so the container starts at once. Both commands print the same kernel release, such as 6.12.0-55.9.1.el10_0.x86_64. A container brings its own files but never its own kernel: every container on a host runs on the host's kernel.

    Each podman run left a stopped container behind. Leave them, and the image, in place: the Manage Container Images exercise lists the image, and the Manage a Container exercise finds and removes the stopped containers.
