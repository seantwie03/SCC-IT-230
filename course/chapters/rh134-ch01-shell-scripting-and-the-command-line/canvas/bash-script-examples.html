Bash Script Examples

Short, self-contained scripts covering everything we wrote in class, in roughly the order we built up to it. Read them, run them, and change them. Each one is small enough to retype from memory, which is the point.

How to use these

Running a script

Save a script to a file, make it executable, then run it by path. Scripts that take arguments show the expected usage in a comment. 

vim greeter.sh
chmod a+x greeter.sh
./greeter.sh

Getting started

1. Hello, world

The smallest useful script. Line 1 is the hashbang, which names the interpreter that will read the rest of the file. 

#!/usr/bin/bash
#
# This script greets the world

echo "Hello, World"

exit 0

2. Prompting for input

read pauses the script and waits for a line from standard input. Try running it normally, then try feeding it a file with ./prompting_greeter.sh < name.txt. 

#!/bin/bash

echo "Enter Name:"
read -r my_name
echo "Hello $my_name"

3. Positional parameters

Arguments arrive as $1, $2, and so on. $0 is the script's own name. Run it with a few arguments and watch which one lands where. 

#!/usr/bin/bash
#
# This script processes 3 arguments

echo "Starting $0"
echo "The first argument is: $1"
echo "The second argument is: $2"
echo "The third argument is: $3"

Loops

4. Looping over every argument

$# is how many arguments arrived and $@ is all of them. Looping over $@ lets one script handle any number of inputs. 

#!/usr/bin/bash
#
# This script processes any number of arguments

echo "You supplied $# arguments"

for arg in $@ ; do
	echo "Argument: $arg"
done

exit 0

In your own scripts, quote it as for arg in "$@" so that arguments containing spaces stay in one piece.

5. Counting with a C-style for loop

When you need a counter rather than a list, Bash offers the three-part form. 

#!/usr/bin/bash
#
# This script loops 5 times

for (( COUNTER=0 ; COUNTER<5 ; COUNTER++ )) ; do
	echo "COUNTER $COUNTER"
done

exit 0

6. Reading a file line by line

The most common loop an administrator writes. The redirection at the end of the loop feeds the file into read. 

#!/usr/bin/bash
#
# This script reads every line in ./6_while.txt

while read -r line; do
    echo "Processing line: $line"
done < 6_while.txt

exit 0

Save this alongside it as 6_while.txt: 

This is line one.
This is line two.
This is line three.
This is line four.

7. Waiting with until

until is while with the condition reversed: it repeats until the condition succeeds. Run this, then create the file from a second terminal and watch the loop end. 

#!/usr/bin/bash
#
# This script will wait until 07_until.txt exists

until [[ -f "07_until.txt" ]]
do
    echo "Waiting for 07_until.txt to exist..."
    sleep 2
done

echo "07_until.txt exists!"

exit 0

Making decisions

8. Falling back to a prompt

-z is true when a string is empty. This script uses an argument when it gets one and asks for a name when it does not. 

#!/usr/bin/bash

if [[ -z "$1" ]] ; then
	echo "Enter a name"
	read NAME
else
	NAME="$1"
fi

echo "Name is $NAME"

exit 0

9. Choosing among several options with case

When one value has several known possibilities, case reads better than a stack of elif branches. The *) branch catches everything else, which is where a usage message belongs. 

#!/usr/bin/bash
#
# This script manages a service

case "$1" in
	start)
		echo "Starting...."
		;;
	stop)
		echo "Stopping..."
		;;
	restart)
		echo "Restarting..."
		;;
	*)
		echo "Usage: $0 (start|stop|restart)"
esac

Putting it together

10. Creating users from a list

A privilege check, a file read line by line, and a test that makes the script safe to run twice. getent passwd asks whether an account already exists, and continue skips to the next line when it does. 

#!/usr/bin/bash

if [[ $EUID -ne 0 ]] ; then
	echo "You must be root to run this script!"
	exit 9
fi

while read -r listed_user; do
	if getent passwd $listed_user >/dev/null ; then
	       echo "User $listed_user already exists"
	       continue
	fi
	echo "Creating user: $listed_user"
	useradd $listed_user
	echo "$listed_user created with user id $(id -u $listed_user)"
done < 10_users.txt

exit 0

Save this alongside it as 10_users.txt: 

billy
molly
emily
jerry
charley
franky
lucy

11. Undoing it again

The companion to the script above. Anything that creates accounts should come with something that removes them, so you can rerun your work from a clean state. 

#!/usr/bin/bash

if [[ $EUID -ne 0 ]] ; then
	echo "You must be root to run this script!"
	exit 9
fi

while read -r listed_user; do
	if ! getent passwd $listed_user >/dev/null ; then
	       echo "User $listed_user does NOT exist"
	       continue
	fi
	echo "Deleting user: $listed_user"
	userdel -r $listed_user
	echo "$listed_user has been deleted"
done < 10_users.txt

userdel -r removes the home directory That is what you want for accounts you just created for practice. Never run it against a real account without checking what lives in that home directory first.

Practice on your own

Inspecting a list of paths

Try this one before you look at anything else. Write a script that inspects each item in the list below:

  • If the item is a regular file, say whether the current user can write to it.
  • If the item is a directory, say whether the current user can search it.
  • Otherwise, say that the item is neither a file nor a directory.
  • Every item must produce at least one message, and every message must name the item. 
/nonexistant
/home/$USER/.bashrc
/etc/hosts
/tmp
/root
/dev/null

Everything you need is in the examples above: a for loop, if and elif, and the -f, -d, -w, and -x tests.
