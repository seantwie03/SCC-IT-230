Exercise

Configure an NFS Server Exercise

Task

Turn servera into an NFS server: install the server, export /srv/reports to the lab network with read/write access, open the firewall, and confirm the export is active. The next exercise mounts this export on workstation.

Host
servera
Prerequisite
None

  1. Install nfs-utils

    Connect to servera from your terminal, then become root. 

    ssh servera
sudo -i
dnf install -y nfs-utils

    nfs-utils provides the nfs-server service and the exportfs and showmount commands. If it is already installed, dnf says so and changes nothing. Remember the package name: it may not be installed on an exam system. While it installs, dnf may print a warning that gssproxy.service changed on disk and suggest systemctl daemon-reload. It is harmless; you do not need to run it.

  2. Create /srv/reports and give it to student

    mkdir /srv/reports
chown student:student /srv/reports
ls -ld /srv/reports

    The listing shows the directory owned by student and group student.

    Why student and not root By default NFS treats root on a client as the unprivileged nobody on the server (root_squash), so root on workstation will not be able to write here. student has UID 1000 on both hosts, so student on workstation can.

  3. Export it read/write to 172.25.250.0/24

    Open /etc/exports, which starts empty, and add this line: 

    vim /etc/exports
    /srv/reports  172.25.250.0/24(rw,sync)

    Save the file and check it.

    cat /etc/exports
    No space before the parenthesis With a space, 172.25.250.0/24 (rw,sync) exports to the subnet read-only and to everyone else read/write. exportfs only warns about it.

  4. Enable and start the nfs-server service

    systemctl enable nfs-server --now

    systemctl reports that it created a symlink in multi-user.target.wants, so the server also starts at every boot. Starting the server reads /etc/exports, so the export is live already. rpcbind and nfs-mountd start with it.

  5. Open the firewall for NFS

    firewall-cmd --add-service=nfs --add-service=rpc-bind --add-service=mountd
firewall-cmd --runtime-to-permanent
firewall-cmd --list-all

    Each firewall-cmd change prints success, and the services: line of the listing now includes mountd, nfs, and rpc-bind. nfs carries the mounts on TCP port 2049; rpc-bind and mountd let workstation ask what is exported with showmount. On the SCC lab the interfaces: line lists two interfaces, enp0s3 and enp0s8.

  6. Verify the export with exportfs -v

    exportfs -v

    One export, with every option it carries:

    /srv/reports    172.25.250.0/24(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)

    rw and sync are the options you wrote. root_squash and the rest are defaults.

    Leave the export in place. The Mount NFS Exports exercise mounts it from workstation, and its cleanup removes it.
