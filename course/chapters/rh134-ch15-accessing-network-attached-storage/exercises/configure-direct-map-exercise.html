Exercise

Configure a Direct Map Exercise

Task

Export a manuals directory from servera and have autofs on workstation mount it at /nfs/manuals the first time anyone uses the path. A direct map names that one fixed path.

Hosts
servera (server), workstation (client)
Prerequisite
Mount NFS Exports Exercise

  1. On servera, create /srv/manuals and export it

    ssh servera
sudo -i
mkdir /srv/manuals
echo "Hold the power button for ten seconds" > /srv/manuals/printer-reset.txt
chown -R student:student /srv/manuals

    Open /etc/exports, which is empty after the previous exercise's cleanup, and add this line: 

    vim /etc/exports
    /srv/manuals  172.25.250.0/24(rw,sync)

    Save the file and check it.

    cat /etc/exports

  2. Reload the exports and verify with showmount --exports 

    exportfs -r
exportfs -v

    exportfs -r applies the edited file without restarting the server, and exportfs -v lists /srv/manuals with its options. Then check from workstation. 

    exit
exit
ssh workstation
showmount --exports servera
    Export list for servera:
/srv/manuals 172.25.250.0/24

  3. On workstation, install autofs

    sudo -i
dnf install -y autofs

  4. Create the master map file in /etc/auto.master.d/

    Create /etc/auto.master.d/direct.autofs with this one line. /- marks a direct map, whose map file holds full paths. 

    vim /etc/auto.master.d/direct.autofs
    /-  /etc/auto.direct
    cat /etc/auto.master.d/direct.autofs

  5. Create the direct map for /nfs/manuals

    Create /etc/auto.direct with the mount point, the options, and the export: 

    vim /etc/auto.direct
    /nfs/manuals  -rw,sync  servera:/srv/manuals
    cat /etc/auto.direct

  6. Enable and start the autofs service

    systemctl enable autofs --now

    systemctl reports the symlink it created, so autofs also starts at every boot. You did not create /nfs/manuals; autofs does.

  7. Verify the share is not mounted, then access the mount point 

    mount | grep /nfs/manuals

    One line, /etc/auto.direct on /nfs/manuals type autofs: that is the trigger autofs watches, not the share. Nothing from servera is mounted yet. Any user can trigger the mount, so use the path as student. 

    exit
ls /nfs/manuals
cat /nfs/manuals/printer-reset.txt

    ls lists printer-reset.txt, which lives on servera.

  8. Verify the share is now mounted

    mount | grep /nfs/manuals

    Two lines now: the autofs trigger, and below it servera:/srv/manuals on /nfs/manuals type nfs4. After five minutes with nothing using it, autofs unmounts the share again and only the trigger stays.

    Grep for the path, not for autofs mount | grep autofs shows only the triggers, never the NFS mount, whose type is nfs4.

  9. Clean up

    No later exercise uses this map or export. Remove the two map files and restart autofs; it stays installed and enabled for the next exercise. 

    sudo -i
rm -f /etc/auto.master.d/direct.autofs /etc/auto.direct
systemctl restart autofs
mount | grep /nfs/manuals

    mount | grep prints nothing, and autofs has removed /nfs/manuals. Then remove the export on servera: open /etc/exports and delete the /srv/manuals line, leaving the file empty. 

    exit
exit
ssh servera
sudo -i
vim /etc/exports
exportfs -r
rm -rf /srv/manuals
