Special Characters in the Shell Exercise

Overview

Bash inspects your command line before the command runs, and it acts on characters such as *, ?, [, and $. Whoever reads them first wins, so a pattern meant for another program has to be hidden from Bash.

In this hands-on exercise you will match file names with each of the three glob patterns, watch Bash expand an unquoted character, protect that character with single quotes, double quotes, and a backslash, and finally use quoting to pass a directory name that contains a space.

Target host
servera

  1. Connect to the lab host and create some files

    Connect to servera and create three empty files in your home directory to experiment on. 

    ssh student@servera
touch filea.txt fileb.md filec.sh
ls

  2. Match file names with a glob

    A glob matches whole file names. Run each of the three patterns and compare which files come back. 

    ls *.txt
ls file?.md
ls file[ac].*
    The three patterns * matches any run of characters, including none. ? matches exactly one character. [ac] matches one character from the set.

  3. Watch Bash expand an unquoted asterisk

    Run echo with a bare asterisk as its argument. 

    echo *
    What happened? echo never received an asterisk. Bash replaced it with the names of the files in the directory and then ran echo with those names.

  4. Protect the asterisk

    Each of the following passes a literal asterisk through to echo. 

    echo '*'
echo "*"
echo \*

    Single quotes protect everything inside them. A backslash protects exactly the one character that follows it.

  5. Assign a variable

    Assign a value with name=value. Do not put spaces around the equals sign. Read the value back by prefixing the name with a dollar sign. 

    linux=awesome
echo To print the value, prefix the variable name with a dollar sign: $linux

  6. Compare single quotes with double quotes

    Run all three commands and read the output of each. 

    echo "Double quotes allow variable expansion: $linux"
echo 'Single quotes do not. They treat everything literally: $linux'
echo 'Single quotes are best when another program must receive the pattern'
    Key idea Double quotes still let Bash expand variables and command substitutions. Single quotes let nothing through, which is why they are the right choice when a pattern must reach another program untouched.

  7. Escape a dollar sign inside double quotes

    A backslash works inside double quotes, so you can keep expansion available and still print one literal character. 

    echo "This prints the dollar sign even though it is in double quotes: \$linux"

  8. Group words into a single argument

    Commands split their arguments on spaces. The following creates two directories, not one. 

    mkdir My Files
ls -l

    Quote the whole name, or escape each space, to pass one argument instead of two. 

    mkdir 'My Files'
mkdir This\ Is\ One\ Argument
ls -l

  9. Clean up

    Remove the directories and files you created.

    rmdir My Files 'My Files' 'This Is One Argument'
rm filea.txt fileb.md filec.sh
ls -l
