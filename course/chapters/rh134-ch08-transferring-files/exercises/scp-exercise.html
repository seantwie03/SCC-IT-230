Copying Files with scp Exercise

Overview

scp is part of the OpenSSH suite and rides on top of ssh, so it works anywhere ssh works — including Windows Terminal on the VDI. Its syntax is cp plus a colon.

In this hands-on exercise you will create a file on your own machine, upload it to servera, edit it there, and download the edited copy back. Then you will move several files at once with a pattern, in both directions.

Local host
Your VDI session or workstation
Remote host
servera

  1. Create a small file locally

    Open Windows Terminal on the VDI. Create a text file named after yourself and write your favorite text editor into it. 

    notepad YOURNAME.txt
    On the Linux workstation If you are working from workstation instead, use vim YOURNAME.txt. Everything after this step is identical on both systems.

  2. Upload the file to servera

    Source first, destination second, exactly like cp. The colon is what makes the second path remote. 

    scp YOURNAME.txt student@servera:~

  3. Confirm the file arrived

    Connect to servera and look for your file. 

    ssh student@servera
ls -l YOURNAME.txt
cat YOURNAME.txt

  4. Edit the file on servera

    Open the file in Vim and add the last game, book, or movie you finished. 

    vim YOURNAME.txt

    Press A to append at the end of the current line, type your addition, press Esc, then type :wq and press Enter. 

    cat YOURNAME.txt
exit

  5. Download the edited file

    Now the colon is on the source, so this is a download. The dot means the current directory. 

    scp student@servera:~/YOURNAME.txt .

    Read the file and confirm your addition made the round trip.

    Key idea Direction is nothing more than argument order. Whichever argument carries the colon is the remote one.

  6. Send several files with one pattern

    Create a few files so a pattern has something to choose between. 

    touch notes.txt report.txt photo.png
ls

    Before running the copy, use echo to see what scp is actually going to receive. 

    echo scp *.txt student@servera:~

    Now run it for real.

    scp *.txt student@servera:~
ssh student@servera ls
    Who did the matching? Bash expanded *.txt on your own machine, before scp started. scp received two file names and never saw a pattern at all — which is why photo.png never left workstation.

  7. Match the pattern on the far end instead

    Move into an empty directory so it is obvious what arrives. 

    mkdir -p ~/from-servera
cd ~/from-servera

    This time the pattern belongs to the remote path, so wrap it in single quotes. 

    scp 'student@servera:*.txt' .
ls -l
    Key idea The quotes keep the pattern intact so it travels to servera and is matched against servera's files. Quoting is how you say which machine does the matching.

  8. Clean up

    Remove the files from both machines.

    cd ~
rm YOURNAME.txt notes.txt report.txt photo.png
rm -rf ~/from-servera
ssh student@servera rm YOURNAME.txt notes.txt report.txt
