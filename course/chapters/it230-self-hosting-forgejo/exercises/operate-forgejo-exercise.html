Exercise

Operate Forgejo Exercise

Task

Run what the last three exercises built. On serverb, write a script that backs up Forgejo's database and files together, keeps the seven newest backups, and copies them to servera, then schedule it nightly at a low priority, with its log rotated. On servera, search httpd's access log for server errors. This is the last exercise of the week.

Hosts
serverb and servera
Prerequisite
Build the Web Tier

  1. Install rsync on serverb and servera

    Every command on serverb in steps 1 to 5 runs as root, so start a root shell there. rsync must be installed at both ends of the copy: 

    ssh serverb
sudo -i
dnf install -y rsync
ssh servera dnf install -y rsync

    root reaches every lab host with a key, so ssh asks for no password. The first time, it may report that it added servera to its known hosts.

  2. Write a script that backs up the database and files, keeps the seven newest, and copies them to servera 

    vim /usr/local/bin/forgejo_backup.sh

    Press i and type:

    #!/bin/bash
backup_dir="/var/backups/forgejo"
run_dir="${backup_dir}/forgejo_$(date --iso-8601=minutes)"
mkdir -p "${run_dir}"
su - postgres -c "pg_dump forgejo" | gzip > "${run_dir}/database.sql.gz"
tar -C /srv -czf "${run_dir}/files.tar.gz" --exclude=forgejo/indexers forgejo
for old_run in $(ls -dt ${backup_dir}/forgejo_* | tail -n +8); do
    rm -r "${old_run}"
done
rsync -av --delete "${backup_dir}/" servera:forgejo-backups/
echo "$(date) wrote ${run_dir}"

    Press Esc, then type :wq and press Enter. Make it executable: 

    chmod a+x /usr/local/bin/forgejo_backup.sh

    What each part does:

    • Each run gets a directory named for the minute it ran, holding both the database and the files, so keeping seven runs keeps seven complete backups. mkdir -p also creates /var/backups/forgejo on the first run.
    • pg_dump, run as postgres, makes a consistent copy of the database even while Forgejo uses it, and gzip compresses it.
    • tar -C /srv works from /srv, so the archive holds forgejo/ and everything in it. --exclude=forgejo/indexers leaves out the search index, which Forgejo can rebuild and which is busy while Forgejo runs.
    • ls -dt lists the run directories newest first, and tail -n +8 prints every one after the seventh, which rm -r deletes. Without the +, tail -n 8 would print the last eight lines, the oldest runs, and the loop would delete those instead.
    • rsync -av --delete mirrors /var/backups/forgejo to forgejo-backups in root's home on servera, deleting the pruned runs there too.
    • The last line writes one line to the log per run.

  3. Run it by hand under nice, and check the copy on servera

    Run it by hand before trusting it to a schedule, at a lower priority than Forgejo's users. 2>&1 sends its errors to the same log as its output: 

    nice -n 10 /usr/local/bin/forgejo_backup.sh >> /var/log/forgejo_backup.log 2>&1

  4. Schedule it nightly in /etc/cron.d

    Copying /etc/crontab gives you its field reference as a starting point: 

    cp /etc/crontab /etc/cron.d/forgejo_backup
vim /etc/cron.d/forgejo_backup

    Press G to go to the last line and o to open a line below it, then type: 

    0 2 * * * root nice -n 10 /usr/local/bin/forgejo_backup.sh >> /var/log/forgejo_backup.log 2>&1

    Press Esc, then type :wq and press Enter. Every day at 2:00, as root, the line runs the same command you ran by hand. Lines in /etc/cron.d name the user that runs them. Check the line: 

    tail -1 /etc/cron.d/forgejo_backup
    0 2 * * * root nice -n 10 /usr/local/bin/forgejo_backup.sh >> /var/log/forgejo_backup.log 2>&1

  5. Rotate the backup's log with logrotate

    vim /etc/logrotate.d/forgejo_backup

    Press i and type:

    /var/log/forgejo_backup.log {
    weekly
    rotate 4
    compress
    missingok
}

    Press Esc, then type :wq and press Enter. logrotate.timer would rotate the log weekly; --force rotates it now, which checks the file: 

    logrotate --force /etc/logrotate.d/forgejo_backup
ls /var/log/forgejo_backup*
    /var/log/forgejo_backup.log.1.gz

    The log was moved aside and compressed. The next run starts a new one.

  6. Search servera's access log for errors

    Leave the root shell, and log in to servera as student. If ssh reports that it added servera to its known hosts, that is expected. 

    exit
ssh servera
sudo grep -E '" 5[0-9]{2} ' /var/log/httpd/access_log
    ::1 - - [21/Nov/2026:18:03:53 +0000] "GET / HTTP/1.1" 503 299 "-" "curl/8.9.1"

    Each line of the access log is one request, and the status follows the quoted request. The pattern's leading quote and space anchor the match there, so it finds statuses from 500 to 599, server errors, and not a 5 anywhere else in the line. This 503 is Build the Web Tier's first curl, before httpd was allowed to reach Forgejo. Count every status: 

    sudo grep -oE '" [0-9]{3} ' /var/log/httpd/access_log | sort | uniq -c
          2 " 200 
      1 " 503

    -o prints only the matches, and sort | uniq -c counts each one. Your log also holds your own requests, such as Firefox's from Build the Web Tier, so your counts differ. This ends the week's exercises.
