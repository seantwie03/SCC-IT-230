Exercise

Build the Data Tier Exercise

Task

Make serverb Forgejo's data tier. Put PostgreSQL's database on a logical volume of its own, and share a second logical volume with servera over NFS for Forgejo's files. The next exercise, Build the App Tier, runs Forgejo on servera and uses both, so leave serverb as this exercise ends.

Host
serverb
Prerequisite
None

  1. Tune serverb for throughput performance

    Every command in this exercise runs as root, so start a root shell on serverb: 

    ssh serverb
sudo -i
dnf install -y tuned
systemctl enable --now tuned
tuned-adm active
    Current active profile: virtual-guest

    tuned chose virtual-guest because serverb is a virtual machine. That profile builds on throughput-performance; a database server wants throughput-performance itself: 

    tuned-adm profile throughput-performance
tuned-adm verify
    Verification succeeded, current system settings match the preset profile.
See TuneD log file ('/var/log/tuned/tuned.log') for details.

  2. Install PostgreSQL and the NFS server

    dnf install -y postgresql-server nfs-utils

    postgresql-server brings the postgresql package with it, which holds the client, psql. The install also creates the postgres account, PostgreSQL's administrator.

  3. Create logical volumes for PostgreSQL's data and Forgejo's files 

    lsblk
    NAME                  MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda                     8:0    0   10G  0 disk
├─sda1                  8:1    0    1M  0 part
├─sda2                  8:2    0    1G  0 part /boot
└─sda3                  8:3    0    9G  0 part
  ├─rhel_serverb-root 253:0    0    8G  0 lvm  /
  └─rhel_serverb-swap 253:1    0    1G  0 lvm  [SWAP]
sdb                     8:16   0    5G  0 disk
sdc                     8:32   0    5G  0 disk
sdd                     8:48   0    5G  0 disk
sr0                    11:0    1 1024M  0 rom
sr1                    11:1    1  7.9G  0 rom  /mnt/dvd

    sdb, sdc, and sdd are blank 5 GB disks, and this exercise uses sdb. Your optical drives, the sr lines, may differ.

    Check your disk names first Disk names can change between boots. If your lsblk shows the 10 GB system disk under another name, pick a blank 5 GB disk instead, and use its name everywhere this exercise says sdb.

    Give the disk one partition that fills it, and mark the partition for LVM. 100% ends the partition at the end of the disk. 

    parted /dev/sdb mklabel gpt
parted /dev/sdb mkpart primary 1MiB 100%
parted /dev/sdb set 1 lvm on
udevadm settle
lsblk /dev/sdb
    NAME   MAJ:MIN RM SIZE RO TYPE MOUNTPOINTS
sdb      8:16   0   5G  0 disk
└─sdb1   8:17   0   5G  0 part

    Each parted command also prints Information: You may need to update /etc/fstab., which you can ignore here. Next, make the partition a physical volume in a volume group of its own, with 2 GiB for PostgreSQL and the rest for Forgejo's files: 

    pvcreate /dev/sdb1
vgcreate vg_data /dev/sdb1
lvcreate --name lv_db --size 2G vg_data
lvcreate --name lv_forgejo --extents 100%FREE vg_data
lvs vg_data
      LV         VG      Attr       LSize  Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  lv_db      vg_data -wi-a-----  2.00g
  lv_forgejo vg_data -wi-a----- <3.00g

    Put an XFS file system on each:

    mkfs.xfs /dev/vg_data/lv_db
mkfs.xfs /dev/vg_data/lv_forgejo

    Make their mount points, then open /etc/fstab to mount them at boot: 

    mkdir /srv/db /srv/forgejo
vim /etc/fstab

    Press G to go to the last line and o to open a line below it, then type these two lines: 

    /dev/vg_data/lv_db /srv/db xfs defaults 0 0
/dev/vg_data/lv_forgejo /srv/forgejo xfs defaults 0 0

    Press Esc, then type :wq and press Enter to save. Reload systemd so it reads the new lines, and mount everything in /etc/fstab: 

    systemctl daemon-reload
mount -av
    /                        : ignored
/boot                    : already mounted
none                     : ignored
/mnt/dvd                 : already mounted
mount: /srv/db does not contain SELinux labels.
       You just mounted a file system that supports labels which does not
       contain labels, onto an SELinux box. It is likely that confined
       applications will generate AVC messages and not be allowed access to
       this file system.  For more details see restorecon(8) and mount(8).
/srv/db                  : successfully mounted
mount: /srv/forgejo does not contain SELinux labels.
       You just mounted a file system that supports labels which does not
       contain labels, onto an SELinux box. It is likely that confined

       this file system.  For more details see restorecon(8) and mount(8).
/srv/forgejo             : successfully mounted

    The SELinux warnings are expected: the new file systems have no labels yet, and steps 4 and 8 give them some. Your lines before them may differ. Confirm both are mounted: 

    df -h /srv/db /srv/forgejo
    Filesystem                      Size  Used Avail Use% Mounted on
/dev/mapper/vg_data-lv_db       2.0G   71M  1.9G   4% /srv/db
/dev/mapper/vg_data-lv_forgejo  3.0G   90M  2.9G   3% /srv/forgejo

  4. Prepare the logical volume for PostgreSQL

    PostgreSQL recommends keeping its data one directory below a mount point, so make that directory and give it to postgres: 

    mkdir /srv/db/pgsql
chown postgres:postgres /srv/db/pgsql
chmod 700 /srv/db/pgsql
ls -ldZ /srv/db /srv/db/pgsql
    drwxr-xr-x. 3 root     root     system_u:object_r:unlabeled_t:s0     19 Nov 21 17:11 /srv/db
drwx------. 2 postgres postgres unconfined_u:object_r:unlabeled_t:s0  6 Nov 21 17:11 /srv/db/pgsql

    The new file system has no labels, and no rule in SELinux's policy covers /srv/db. Add one that gives it PostgreSQL's type, then apply it: 

    semanage fcontext -a -t postgresql_db_t '/srv/db(/.*)?'
restorecon -Rv /srv/db
    Relabeled /srv/db from system_u:object_r:unlabeled_t:s0 to system_u:object_r:postgresql_db_t:s0
Relabeled /srv/db/pgsql from unconfined_u:object_r:unlabeled_t:s0 to unconfined_u:object_r:postgresql_db_t:s0

  5. Initialize PostgreSQL on its logical volume

    The postgresql service finds its data through the PGDATA variable. Change it with a drop-in rather than by editing the unit file, which a package update would replace: 

    systemctl edit postgresql

    systemctl edit opens a new drop-in file in vim, with the cursor between two marker comments. Press i and type these two lines: 

    [Service]
Environment=PGDATA=/srv/db/pgsql/data

    Press Esc, then type :wq and press Enter. 

    Successfully installed edited file '/etc/systemd/system/postgresql.service.d/override.conf'.

    The drop-in comes after the unit file, so its PGDATA replaces the unit's: 

    systemctl cat postgresql | tail -3
    # /etc/systemd/system/postgresql.service.d/override.conf
[Service]
Environment=PGDATA=/srv/db/pgsql/data

    Create the database files in the new PGDATA: 

    postgresql-setup --initdb
ls -ldZ /srv/db/pgsql/data
     * Initializing database in '/srv/db/pgsql/data'
 * Initialized, logs are in /var/lib/pgsql/initdb_postgresql.log
drwx------. 20 postgres postgres unconfined_u:object_r:postgresql_db_t:s0 4096 Nov 21 17:12 /srv/db/pgsql/data

    The new files inherit the label you gave /srv/db in step 4.

  6. Allow the forgejo user to connect to PostgreSQL from servera

    PostgreSQL listens only on localhost until listen_addresses adds serverb's lab address, 172.25.250.11. Open its main configuration file: 

    vim /srv/db/pgsql/data/postgresql.conf

    Type /^#listen_addresses and press Enter to find the commented default, then press o to open a line below it and type: 

    listen_addresses = 'localhost,172.25.250.11'

    Press Esc, then type :wq and press Enter. listen_addresses only picks where PostgreSQL listens. Who may connect is up to pg_hba.conf and the firewall: 

    vim /srv/db/pgsql/data/pg_hba.conf

    Press G and o to add a line at the end, and type: 

    host    forgejo    forgejo    172.25.250.10/32    scram-sha-256

    Press Esc, then type :wq and press Enter. The line's fields are the connection type, the database, the user, the client address, and the authentication method: network connections to the forgejo database, as the forgejo user, from servera (172.25.250.10) only, with a password.

  7. Start PostgreSQL and create the forgejo user and database 

    systemctl enable --now postgresql
    Created symlink '/etc/systemd/system/multi-user.target.wants/postgresql.service' → '/usr/lib/systemd/system/postgresql.service'.

    Become postgres, PostgreSQL's administrator, and start its client: 

    su - postgres
psql
    psql (16.8)
Type "help" for help.

postgres=#

    At the postgres=# prompt, create the user and a database it owns. Each SQL statement ends with ;; without one, psql waits for more at a postgres-# prompt. 

    CREATE USER forgejo WITH PASSWORD 'redhat';
CREATE DATABASE forgejo OWNER forgejo;
    CREATE ROLE
CREATE DATABASE

    PostgreSQL calls users roles, so CREATE USER answers CREATE ROLE. Quit psql, whose own commands start with a backslash and need no ;, then leave the postgres shell: 

    \q
exit

  8. Share Forgejo's logical volume with servera over NFS

    NFS keeps each file's owner as a UID. Forgejo will run as the user forgejo, UID 2000, on servera, so create the same user here to own the share: 

    useradd -u 2000 forgejo
chown forgejo:forgejo /srv/forgejo
restorecon -Rv /srv/forgejo
    Relabeled /srv/forgejo from system_u:object_r:unlabeled_t:s0 to system_u:object_r:var_t:s0

    Like /srv/db, the new file system had no label. No rule needs adding: restorecon gives it var_t, the default for /srv. Now share it with servera: 

    vim /etc/exports

    Press i and type:

    /srv/forgejo servera.lab.example.com(rw)

    Press Esc, then type :wq and press Enter. Start the NFS server and check the export: 

    systemctl enable --now nfs-server
exportfs -v
    Created symlink '/etc/systemd/system/multi-user.target.wants/nfs-server.service' → '/usr/lib/systemd/system/nfs-server.service'.
/srv/forgejo  servera.lab.example.com(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)

  9. Open the firewall for PostgreSQL and NFS

    firewall-cmd --permanent --add-service=postgresql
firewall-cmd --permanent --add-service=nfs --add-service=rpc-bind --add-service=mountd
firewall-cmd --reload
firewall-cmd --list-services
    success
success
success
cockpit dhcpv6-client mountd nfs postgresql rpc-bind ssh

    rpc-bind and mountd are only for showmount, which the next exercise uses from servera. Leave serverb as it is: Build the App Tier connects Forgejo on servera to this database and this share.
