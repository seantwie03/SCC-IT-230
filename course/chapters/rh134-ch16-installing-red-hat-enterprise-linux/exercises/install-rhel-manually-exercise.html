Exercise

Install RHEL Manually Exercise

Task

Create a new VirtualBox virtual machine named serverc on your VDI and install Red Hat Enterprise Linux 10.0 on it by hand from the DVD ISO, with standard partitions and the lab's network settings. The values to use are on the "Install Settings for serverc" slide; this page repeats them except for the passwords, which are the lab's usual ones.

Start the installer early On the VDI, the installer takes a long time to load and install. In class, you create the virtual machine and select the Install entry (steps 1 and 2) at the start of the topic, so it loads while the slides are presented; the remaining steps come after them.
Host
A new VirtualBox virtual machine, serverc, on your VDI
Installation media
C:\Temp\VMs\IT-230\rhel-10.0-x86_64-dvd.iso
Prerequisite
None

  1. Create the serverc virtual machine in VirtualBox

    In VirtualBox Manager, click New. Name the machine serverc, set VM Folder to C:\Temp\VMs\IT-230\IT-230, and select the DVD ISO above as its ISO Image. Leave Proceed with Unattended Installation unchecked: this exercise installs by hand.

    Under Specify virtual hardware, give it 2048 MB of memory and 2 CPUs, and leave Use EFI unchecked. Under Specify virtual hard disk, create a new 10 GB virtual hard disk; VirtualBox places it in the VM's folder, at C:\Temp\VMs\IT-230\IT-230\serverc\serverc.vdi. Click Finish. 2048 MB is enough for the installer and leaves room on the VDI for workstation and servera.

    Before starting it, open its Settings and then Network. Leave Adapter 1 attached to NAT. Enable Adapter 2, attach it to Internal Network, and set its name to intnet, the same network as Adapter 2 of servera.

    Why two adapters Adapter 1 reaches the internet through VirtualBox's NAT. Adapter 2 joins the private network that servera and workstation share, where the lab's addresses live.

  2. Boot it from the RHEL 10.0 DVD

    Start serverc. At the boot menu, select Install Red Hat Enterprise Linux 10.0. On the welcome screen, keep English (United States) and click Continue. The Installation Summary opens: every later step starts from it, and Done returns you to it.

    Mouse drift During the installation you may see two mouse pointers, the VDI's and the virtual machine's, that do not line up. Move slowly and click where the virtual machine's own pointer is.

  3. Set the time zone and software selection

    In Time & Date, set Region to Etc and City to Coordinated Universal Time. In Software Selection, choose Minimal Install, which installs only what a server needs to run.

  4. Create standard partitions for /boot, swap, and /

    Open Installation Destination, select the 10 GiB disk, choose Custom under Storage Configuration, and click Done. On the Manual Partitioning screen, set New mount points will use the following partitioning scheme to Standard Partition before adding anything; the default is LVM, which next week covers. Then click + to add each mount point:

    • biosboot: 1 MiB, which Anaconda lists as BIOS Boot
    • /boot: 1 GiB, file system xfs
    • swap: 1 GiB, file system swap
    • /: leave the size empty so it takes the rest of the disk, file system xfs

    Check that each one shows Standard Partition as its Device Type, then click Done. The Summary of Changes dialog lists a new GPT partition table and the four partitions; click Accept Changes.

    Why a BIOS boot partition The VM boots with BIOS, since Use EFI is unchecked, and Anaconda gives the disk a GPT partition table. That combination needs a small BIOS boot partition to hold part of the boot loader.

  5. Configure the network and host name

    Open Network & Host Name. Two interfaces are listed: enp0s3 is Adapter 1 (NAT) and enp0s8 is Adapter 2 (the lab network).

    • enp0s3 is already connected and gets its address automatically.
    • Select enp0s8 and click Configure. On the IPv4 Settings tab, set Method to Manual, click Add, and enter the address 172.25.250.12 with netmask 24. Leave the gateway and DNS servers empty, click Save, and turn the interface on.
    • Set Host Name to serverc and click Apply.
    No gateway on the lab network The internal network has no router, so a gateway there would point at nothing. Internet traffic goes out through enp0s3 instead.

  6. Enable root and create the student administrator

    In Root Account, select Enable root account, set the lab's root password, and select Allow root SSH login with password. RHEL 10 disables root unless you enable it, and refuses password logins as root over SSH unless you allow them.

    In User Creation, enter the full name Student User and user name student, select Add administrative privileges to this user account (wheel group membership), keep Require a password to use this account selected, and set the lab's student password. An administrator is added to the wheel group and can use sudo.

    Weak passwords need Done twice The lab passwords are short, so Anaconda rates them weak and asks you to press Done again to use the password anyway. Do so here; never do this outside a lab.

  7. Begin the installation and reboot

    When no item on the summary shows a warning triangle, click Begin Installation. Nothing is written to the disk before this. When the progress screen reports that the installation is complete, click Reboot System.

  8. Verify with hostname, ip addr, and lsblk

    Log in on the console as student.

    hostname
ip addr
lsblk

    hostname prints serverc. ip addr shows 172.25.250.12/24 on enp0s8 and 10.0.2.15/24, from VirtualBox's NAT, on enp0s3. lsblk shows sda with four partitions: sda1 (1M, the BIOS boot partition), sda2 on /boot, sda3 as [SWAP], and sda4 on /, with no LVM volumes.
