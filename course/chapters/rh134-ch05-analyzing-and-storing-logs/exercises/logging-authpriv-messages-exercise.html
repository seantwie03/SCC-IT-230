Logging authpriv.info Messages Exercise

Task

Send authentication messages to a file of your own by adding a rule to rsyslog, then watch what else the rule catches.

Host
servera
Facility
authpriv
Priority
info
Log location
/var/log/authpriv-info

  1. Add a rule for authpriv.info

    Become root, then create a drop-in file. Files in /etc/rsyslog.d/ are read alongside /etc/rsyslog.conf, so you never edit the main file. 

    sudo -i
vim /etc/rsyslog.d/authpriv-info.conf

    Press i and write one rule: the facility and priority on the left, the destination file on the right. 

    authpriv.info /var/log/authpriv-info

    Leave insert mode with jj, save with :wq, and read it back. 

    cat /etc/rsyslog.d/authpriv-info.conf

  2. Restart rsyslog

    rsyslog reads its configuration when it starts, so a new rule does nothing until you restart the service. 

    systemctl restart rsyslog
systemctl is-active rsyslog
ls -l /var/log/authpriv-info
    The file appears on restart rsyslog creates the destination as soon as the rule loads, before any message arrives.

  3. Send a test message

    logger writes a message to syslog. -p chooses the facility and priority, which is what decides where the message lands. 

    logger -p authpriv.info "Houston, we have a problem."
cat /var/log/authpriv-info

  4. Watch the file fill as you authenticate

    Your message is not the only thing matching this rule. Every login and every sudo is an authpriv event. 

    less /var/log/authpriv-info

    Press G to jump to the end and q to quit. Open a second terminal, connect to servera again, then look at the tail of the file. 

    tail -n5 /var/log/authpriv-info
    This is why authpriv is separate Authentication records go to a restricted file rather than /var/log/messages, which is why the default rules send authpriv.* to /var/log/secure and exclude it from messages.

  5. Confirm higher priorities land in the same file

    A rule naming info catches info and everything more severe. Send two messages well above it. 

    logger -p authpriv.alert "Houston, we have an alert!"
logger -p authpriv.emerg "Houston, we have an EMERGENCY!"
tail -n2 /var/log/authpriv-info
    Emergencies go everywhere The default rules also include *.emerg :omusrmsg:*, which writes emergency messages to every logged-in terminal. Do not be surprised when that one appears on screen.

  6. Clean up

    Remove the rule and the file it created, then restart rsyslog so it forgets them. 

    rm -f /etc/rsyslog.d/authpriv-info.conf /var/log/authpriv-info
systemctl restart rsyslog
ls /etc/rsyslog.d/
