Exercise

A Service That Checks Before It Runs Exercise

Task

Sync /etc from servera to workstation, wrapped in a systemd service that refuses to run when workstation cannot be reached. Cron would run the job regardless and leave you to handle the failure in your own script.

Hosts
servera and workstation
Sync
/etc to /tmp/etc_from_servera
Runs as
root
Refuses when
workstation is unreachable

  1. Write the sync script

    Become root and install rsync, which servera does not have. Remember that rsync must exist on both ends. 

    sudo -i
dnf install -y rsync

    Write the script with a proper hashbang and its settings as variables, so the host and destination are named once. 

    vim /usr/local/bin/etc_sync.sh
    #!/bin/bash
TARGET_HOST="workstation"
TARGET_DIR="/tmp/etc_from_servera"

rsync -a --delete /etc/ "${TARGET_HOST}:${TARGET_DIR}/"

    Make it executable and run it once by hand. Never hand systemd a command you have not run yourself. 

    chmod a+x /usr/local/bin/etc_sync.sh
/usr/local/bin/etc_sync.sh
ssh workstation 'ls /tmp/etc_from_servera | head -3'

  2. Write a service unit for it

    A service unit says how to run something. This one adds a condition that is checked before every run. 

    vim /etc/systemd/system/etc-sync.service
    [Unit]
Description=Sync /etc to workstation

[Service]
Type=oneshot
ExecCondition=/usr/bin/ping -c1 -W2 workstation
ExecStart=/usr/local/bin/etc_sync.sh

    Tell systemd to re-read the unit files.

    systemctl daemon-reload
    No [Install] section, on purpose Step 4 shows what that costs you, and why this service does not need it.

  3. Start it and read the journal

    Start the unit by hand and look at what systemd recorded. 

    systemctl start etc-sync.service
systemctl status etc-sync.service --no-pager
journalctl -u etc-sync.service -n 10 --no-pager
    Type=oneshot finishes The unit runs to completion and returns to inactive (dead). That is success for a job, not a failure.

  4. Try to enable it

    Enabling is what makes a unit start on its own. Try it. 

    systemctl enable etc-sync.service

    systemd refuses, and explains why:

    The unit files have no installation config (WantedBy=, RequiredBy=, UpheldBy=,
Also=, or Alias= settings in the [Install] section...). This means they are not
meant to be enabled or disabled using systemctl.
    This service is not meant to be enabled It has no [Install] section because nothing should start it at boot. A timer will start it instead, and the timer is what gets enabled.

  5. Break the check and watch the run be skipped

    Point the condition at an address that does not answer. 

    vim /etc/systemd/system/etc-sync.service

    Search for the line with /ExecCondition, press cc to replace it, and type: 

    ExecCondition=/usr/bin/ping -c1 -W2 192.0.2.99

    Reload and start it again.

    systemctl daemon-reload
systemctl start etc-sync.service
echo "exit status: $?"
systemctl is-failed etc-sync.service
journalctl -u etc-sync.service -n 5 --no-pager

    The journal names exactly what happened:

    systemd[1]: etc-sync.service: Skipped due to 'exec-condition'.
    Skipped is not failed The start command exits 0 and the unit is not marked failed. A job that correctly declines to run is not an error, so nothing pages you at 2 a.m. In cron you would write this check into the script yourself and hope it stays there.

  6. Restore the check

    Put the reachable host back, so the service works for the next exercise. 

    vim /etc/systemd/system/etc-sync.service

    Search with /ExecCondition, replace the line with cc: 

    ExecCondition=/usr/bin/ping -c1 -W2 workstation
    systemctl daemon-reload
systemctl start etc-sync.service
systemctl is-failed etc-sync.service
    Leave this in place The timer exercise schedules this same unit and cleans up both when it finishes.
