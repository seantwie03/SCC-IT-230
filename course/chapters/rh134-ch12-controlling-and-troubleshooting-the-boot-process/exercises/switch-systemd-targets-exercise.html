Switch systemd Targets Exercise

Task

Move workstation between systemd targets in three ways: on the running system with systemctl isolate, at every boot with systemctl set-default, and for a single boot with systemd.unit= at the GRUB2 menu. workstation normally boots to a graphical login, so each change is easy to see in its VM window. The GRUB2 menu and the rescue shell appear before the network is up, so those steps happen in the workstation VM window, not in your SSH session.

Host
workstation
Console
The workstation VM window

  1. Make the GRUB2 menu appear on every boot

    Connect to workstation from your terminal, then become root. 

    ssh workstation
sudo -i
grub2-editenv - unset menu_auto_hide
grub2-editenv - list

    menu_auto_hide is no longer in the list, so the menu and its countdown appear at every boot. Step 6 needs the menu.

  2. Inspect the default target and its dependencies

    systemctl get-default
systemctl list-dependencies graphical.target

    workstation boots to graphical.target. The dependency tree opens in a pager: near the top, graphical.target pulls in gdm.service, the display manager that draws the graphical login, and multi-user.target, which brings everything a text-only system runs. A ● marks an active unit and a ○ an inactive one. Press q to leave the pager.

  3. Switch to multi-user.target without rebooting

    Bring the workstation VM window forward so you can watch it, then switch targets from your SSH session. 

    systemctl isolate multi-user.target
systemctl is-active graphical.target multi-user.target
systemctl get-default

    systemctl isolate prints nothing. In the VM window, the graphical login screen gives way to a text login. systemctl is-active answers once per target: graphical.target is inactive, and multi-user.target is still active. Your SSH session survives, because sshd belongs to multi-user.target. The default is still graphical.target, so the next boot would bring the graphical login back.

  4. Make multi-user.target the default and reboot to confirm 

    systemctl set-default multi-user.target
systemctl get-default
systemctl reboot

    set-default reports that it removed /etc/systemd/system/default.target and created it again as a link to multi-user.target. Let the GRUB2 countdown run out. workstation boots to a text login, with no graphical login screen. When it has finished booting, connect again and check. 

    ssh workstation
systemctl get-default
systemctl is-active graphical.target

    The default is multi-user.target, and graphical.target is inactive: the change lasted across the reboot.

  5. Restore graphical.target as the default

    sudo -i
systemctl set-default graphical.target
systemctl get-default

    The link points at graphical.target again. Nothing graphical starts yet; the change takes effect at the next boot.

  6. Boot once into rescue.target from the GRUB2 menu

    Bring the workstation VM window forward first, since the menu appears there. Then reboot from your SSH session, which ends as workstation restarts. 

    systemctl reboot

    When the GRUB2 menu appears in the VM window:

    1. Press any key except Enter, such as an arrow key, to stop the countdown.
    2. Press e to edit the highlighted entry.
    3. Use the arrow keys to move to the line that starts with linux. It may continue onto the next screen line.
    4. Press End to jump to the end of that line, then type a space and systemd.unit=rescue.target.
    5. Press Ctrl+X to boot with the change.

    The boot stops at a message that you are in rescue mode, followed by a prompt for the root password for maintenance. Type the root password. You get a root shell on the console, with no network and no SSH.

  7. Confirm the root file system is read/write, then continue the boot

    Type these in the rescue shell, in the VM window:

    mount | grep ' / '
exit

    The line for / lists rw among its options: rescue.target mounts the local file systems read/write, so you could edit a broken configuration file here. exit leaves the shell, and the boot continues to the default target, graphical.target, which brings the graphical login screen back. The systemd.unit= argument lasted one boot.

    When the graphical login appears, connect again from your terminal and check. 

    ssh workstation
systemctl is-active graphical.target

    graphical.target is active.

  8. Clean up

    Hide the GRUB2 menu again, so workstation boots straight past it as it did before this exercise. 

    sudo -i
grub2-editenv - set menu_auto_hide=1
grub2-editenv - list

    The list includes menu_auto_hide=1 again. The default target is already back to graphical.target.
