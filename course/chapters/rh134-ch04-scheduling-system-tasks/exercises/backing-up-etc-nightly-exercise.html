Backing Up /etc/passwd Nightly Exercise

Task

Back up /etc/passwd every night at 10 p.m. as root, copying each snapshot to another host so it is not lost with the machine. servera is a server that never sleeps, so a system crontab suits it. Treat workstation as a laptop that is closed at 10 p.m., and give the same script to anacron instead.

Hosts
servera, then workstation
Back up
/etc
Snapshot to
workstation:/tmp
Runs as
root
Schedule
every night at 10 p.m.

  1. Write the backup script on servera

    Become root, because everything here is system-wide. 

    sudo -i
vim /usr/local/bin/etc_backup.sh

    Give it a hashbang and keep its settings in variables, so the destination host is named once rather than buried in a command. 

    #!/bin/bash
BACKUP_HOST="workstation"
SNAPSHOT="/tmp/passwd_$(date --iso-8601=minutes)"

cp /etc/passwd "${SNAPSHOT}"
scp -q "${SNAPSHOT}" "${BACKUP_HOST}:/tmp/"

    Make it executable and run it once by hand, then check both ends. 

    chmod a+x /usr/local/bin/etc_backup.sh
/usr/local/bin/etc_backup.sh
ls -l /tmp/passwd_*
ssh workstation 'ls -l /tmp/passwd_*'
    A backup on one machine is not a backup The scp line is what makes this useful. If servera dies, the snapshot dies with it.

  2. Schedule it in /etc/cron.d

    Copy /etc/crontab as a starting point. You get the field reference in the comments and leave the original untouched. 

    cp /etc/crontab /etc/cron.d/backups
vim /etc/cron.d/backups

    Press G for the last line and o to open one below it. Add a test schedule that runs every minute: 

    * * * * * root etc_backup.sh
    The extra field A system crontab has root between the five time fields and the command. Your own crontab has no such field, because every job in it already runs as you.

  3. Find out why nothing happened

    Wait for the next minute, then look for a new snapshot. 

    ls -l /tmp/passwd_*
grep etc_backup /var/log/cron

    No new snapshot, and the log says why:

    CROND[...]: (root) CMD (etc_backup.sh)
CROND[...]: (root) CMDOUT (/bin/bash: line 1: etc_backup.sh: command not found)
    Cron's PATH is not your PATH Your shell searches /usr/local/bin; a cron job searches only /usr/bin:/bin:/usr/sbin:/sbin. The script is invisible to it. This is true of user crontabs too.

    Fix it with an absolute path. Press G, then C to replace the line: 

    vim /etc/cron.d/backups
    * * * * * root /usr/local/bin/etc_backup.sh

  4. Confirm root ran it, then set the real schedule

    Wait another minute, then check the log and both hosts. 

    grep etc_backup /var/log/cron
ls -l /tmp/passwd_*
ssh workstation 'ls -l /tmp/passwd_*'

    The log names the user the job ran as:

    CROND[12124]: (root) CMD (/usr/local/bin/etc_backup.sh)
CROND[12123]: (root) CMDEND (/usr/local/bin/etc_backup.sh)

    It works, so give it the schedule you actually want. Press G and cc again: 

    vim /etc/cron.d/backups
    0 22 * * * root /usr/local/bin/etc_backup.sh
    tail -1 /etc/cron.d/backups

  5. Give the same script to anacron on workstation

    That schedule suits a server. Now treat workstation as a laptop: closed and asleep at 10 p.m., so a crontab entry would never fire. Leave the root shell, connect, and become root there. 

    exit
ssh workstation
sudo -i

    Write a local-only version into /etc/cron.daily/ and make it executable. A script that is not executable is silently ignored. 

    vim /etc/cron.daily/etc_backup.sh
    #!/bin/bash
SNAPSHOT="/tmp/passwd_$(date --iso-8601=minutes)"

cp /etc/passwd "${SNAPSHOT}"
    chmod a+x /etc/cron.daily/etc_backup.sh
    No schedule to write There are no time fields here. You are asking for “about once a day” and letting anacron pick the moment.

  6. Let anacron catch up

    Anacron records the date it last ran each group of jobs. Look at that date, then ask it to run anything overdue. 

    cat /var/spool/anacron/cron.daily
anacron -n
ls /tmp/passwd_*

    Nothing happened, because today's daily job is not overdue. Now pretend the laptop has been closed since January and ask again. 

    echo 20260101 > /var/spool/anacron/cron.daily
anacron -n
ls -l /tmp/passwd_*
cat /var/spool/anacron/cron.daily

    The backup ran and the recorded date caught up to today. The job was missed, and anacron noticed.

  7. Clean up both hosts

    Remove the laptop side first, while you are still on it. 

    rm -f /etc/cron.daily/etc_backup.sh /tmp/passwd_*
exit
exit

    Those two exit commands drop the root shell and then the ssh session, leaving you back on servera. 

    sudo rm -f /etc/cron.d/backups /usr/local/bin/etc_backup.sh /tmp/passwd_*
ls /etc/cron.d/
